### Workflow palettes (authority + consistency)

- **Manifest-backed labels** — [`shared/workflow_graph_step_kinds.json`](shared/workflow_graph_step_kinds.json) carries **`palette_handle`** and **`editor_label`** per executable row; **`palette_extras`** documents pseudo-handles (annotations, **`any`**, **`workflow`**, families, **`start`** / **`stop`**, …). Backend parity tests require alignment with **`DEFAULT_PALETTE_COLORS`** in [`backend/app/domain/palette_defaults.py`](backend/app/domain/palette_defaults.py).
- **Rich palette API payloads** — `GET` / create / update palettes return **`entries`**, **`effective_colors`**, and **`warnings`** (unknown or deprecated keys surfaced without blocking reads). Writes reject unknown palette keys and invalid CSS color strings (**`422`**). **`POST /api/v1/palettes/validate`** supports import preview **without persisting**.
- **Frontend** — Editor and Palette Manager consume **`effective_colors`**; palette JSON import uses **`validate`**; OpenAPI-aligned types live under [`frontend/src/generated/palette-types.ts`](frontend/src/generated/palette-types.ts) (run **`npm run codegen:palette-types`** from **`frontend/`** after schema changes). **Effective canvas palette** is **`GET /api/v1/palettes/resolve`** (optional **`workflow_id`**): **`workflow.palette_id`** → **`preferred_editor_palette_id`** → **default**; the SPA uses local list + **`resolveFallbackWorkflowPalette`** only as a defensive fallback.

### Workflow Build (async DAG + SSE)

- **`POST …/runs` + SSE** — Workflow Editor Build enqueues **`POST /api/v1/workflow-definitions/{id}/runs`** (responds immediately with **`{ run_id, status: queued }`**) and subscribes to **`GET /api/v1/workflow-runs/{run_id}/events`** (**`text/event-stream`**) for **`workflow.started`** / **`node.*`** / **`workflow.completed`** (and **`input_required`**, **`transcription_job_status`**, keepalive comments). Long-lived **`POST …/run_stream`** NDJSON and **`POST …/reattach-stream`** are removed; transcription tail/replay uses the same **`…/events`** URL.
- **Poll snapshot** — **`GET /api/v1/workflow-runs/{run_id}`** returns status/timestamps and **`last_event_seq`** when SSE is unavailable or for lightweight polling.
- **Concurrency grid** — New env knobs **`WORKFLOW_MAX_CONCURRENT_NODES`**, **`WORKFLOW_MAX_CONCURRENT_LLM_CALLS`**, **`WORKFLOW_MAX_CONCURRENT_BROWSER_TASKS`**, **`WORKFLOW_MAX_CONCURRENT_EXTERNAL_SKILL_TASKS`**, and **`WORKFLOW_MAX_CONCURRENT_TTS_TASKS`** complement wave batch scheduling; LM slots still **`min`** with **`User.settings.max_concurrent_lm_studio_calls`**.
- **Run preflight (execution budget)** — Before **`POST …/run`** and **`POST …/runs`**, the API evaluates [`execution_preflight.py`](../backend/app/domain/execution_preflight.py): a conservative upper bound on per-run node steps from For Loops (list primitives, **`max_iterations`**, merged **`max_loop_iterations`**). Returns **422** with **`error: preflight_blocked`** when the bound **clearly** exceeds **`max_node_executions`** with no ambiguous inputs; **422** with **`error: preflight_warnings`** when nested workflows or uncertain loop lists require the client to confirm and retry with **`acknowledge_preflight_warnings: true`**. Structural validation (cycles, For Loop / End, Try/Catch regions) runs in the same pass so invalid graphs fail before enqueue when possible.

### API / LM Studio

Per-user **My Settings** keys still apply to **chat** and **workflow** LLM calls. ### Workflow runtime (LLM input hygiene)

- **Reusable text-noise filter** — New module [`backend/app/core/text_noise.py`](backend/app/core/text_noise.py) is the single source of truth for cleaning HTML-derived bodies before they reach LLMs, run logs, or downstream graph nodes. Configurable via the frozen dataclass **`NoiseFilterConfig`** (invisible-character strip, `<style>` / `<script>` drop, repeated-separator collapse, long-URL shortening, whitespace collapse, optional quoted-reply / marketing-footer removal, final `max_chars` cap). Three presets ship: **`DEFAULT_NOISE_FILTER`** (generic), **`EMAIL_BODY_NOISE_FILTER`** (used by Gmail body extraction), and **`EMAIL_HEADER_NOISE_FILTER`** (lighter touch for short header-style fields).
- **Gmail `body_text`** — `curated_gmail_message_from_full_api()` ([`workflow_executor/diagnostics.py`](backend/app/domain/workflow_executor/diagnostics.py)) now runs the curated `body_text` through `EMAIL_BODY_NOISE_FILTER`. The HTML→text path also ignores `<style>` / `<script>` content (previous parser kept the data inside those tags, which produced multi-thousand-token CSS blobs in marketing emails). Final cap **lowered from 32,768 → 8,000** characters; `body_truncated` continues to flag over-cap messages. Tune by editing the preset or passing `max_body_chars`. The Simple LLM Call slimmer in [`gmail_llm_prompt.py`](backend/app/domain/workflow_executor/gmail_llm_prompt.py) now delegates `strip_invisible_email_text_for_llm` to the same module so both layers stay in lockstep. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) and [docs/WORKFLOW_SKILLS.md](docs/WORKFLOW_SKILLS.md).
- **Gmail noise filter — v2 defaults** — `EMAIL_BODY_NOISE_FILTER` adds four new on-by-default knobs: **`normalize_line_endings`** (`\r\n` / lone `\r` → `\n` so the rest of the pipeline sees one form), **`unescape_html_entities`** (`&zwnj;` / `&nbsp;` / `&#x200B;` collapse with the invisible-Unicode pass instead of leaking ~100x repeats from plain-text MIME parts), **`strip_tracking_url_params`** (conservative allow-list: `utm_*`, `mc_cid`, `mc_eid`, `fbclid`, `gclid`, `gbraid`, `wbraid`, `msclkid`, `_hsenc`, `_hsmi`, `ref`, `aff`, `cid`, `eid`, `mkt_tok`, etc. — runs **before** the long-URL length check so URLs whose only bulk was tracking survive), and **`strip_orphan_link_placeholders`** (drops lines whose entire payload is a `[link]` placeholder + surrounding punctuation/whitespace). **`strip_marketing_footers`** is now **on by default** for `EMAIL_BODY_NOISE_FILTER` (existing conservative pattern set: `unsubscribe`, `view in browser`, `manage preferences`, `follow us`, `privacy policy`, `copyright ©`). New **`EMAIL_HEADER_NOISE_FILTER`** preset (invisible-Unicode + entity cleanup + whitespace collapse only — no truncation, no URL changes, no footer stripping) is now applied at extraction time to **`snippet`**, **`subject`**, **`from`**, **`to`**, **`date`** so those fields stop carrying invisible-character padding from marketing senders. All knobs remain configurable per call via `NoiseFilterConfig`.

### Workflow runtime

- **LM Studio — cold model + parallel workflow LLM steps** — After native **`POST /api/v1/models/load`**, the provider **polls** **`GET /api/v1/models`** until **`loaded_instances`** appears ( **`LMSTUDIO_MODEL_READY_MAX_WAIT_SECONDS`**, default **60**; **`0`** disables). **`POST /v1/chat/completions`** (OpenAI-compat route used by **Simple LLM Call**) retries **500** / **504** in addition to **429** / **502** / **503** (within **`LMSTUDIO_CHAT_RETRY_BUDGET_SECONDS`**). See [docs/OPERATIONS.md](docs/OPERATIONS.md#local-llm-timeouts-simple-llm-call--lm-studio), [backend/README.md](backend/README.md#environment-variables).
- **`execute_scheduled_run` terminal SSE** — After **`workflow.started`**, failures during graph validation and setup (not only inside the main loop) emit **`workflow.failed`** **`data:`** payloads over **`GET …/events`** so chunked streams still reach a definitive terminal envelope.

- **Workflow resilience (Spec 02)** — Optional **`graph.execution_limits`** plus per-request **`WorkflowRunRequest.execution_limits`** merge under **`WORKFLOW_EXECUTION_DEFAULT_*`** / **`WORKFLOW_EXECUTION_CEILING_*`** in **`config.py`**; **`GET /api/v1/workflow-execution-limits/`** returns defaults + ceilings for the SPA. **`TryCatchControlNode`** runs validated **`try`/`catch`** regions; global DAG cycle detection **omits edges into the node’s optional `value` handle** (`_edges_for_global_cycle_detection`) so producer-feedback **`value`** wiring is legal. **`For Loop`** adds **`iteration_mode`** (**`sequential`**, **`parallel`**, **`batched`**) alongside legacy **`parallel_iterations`**, optional **`continue_on_error`**, **`summary`**, and batch-size ceilings. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), [docs/OPERATIONS.md](docs/OPERATIONS.md), [backend/README.md](backend/README.md).

- **For Loop — parallel iterations** — Optional **`data.parallel_iterations`** (default off) runs each list item’s body **concurrently** with isolated per-iteration outputs; **`Add to List`** merges segments in **list index order**; validation rejects a **nested For Loop** in that body. Editor checkbox under **For Loop → Execution**; last **Add to List** run result shows the merged list. **Check Email** (`8aea7c97-f73e-4176-beaa-624fc14725b2`): enable in the DB with [`backend/scripts/enable_parallel_for_loop_check_email.py`](backend/scripts/enable_parallel_for_loop_check_email.py) when **`DATABASE_URL`** points at the target database. See [docs/WORKFLOW_SKILLS.md](docs/WORKFLOW_SKILLS.md).

- **Parallel For Loop + Simple LLM** — **Persona**/`Structure` ORM reads in **Simple LLM Call** use an **`asyncio` lock** so concurrent loop iterations do not share unsafe **`Session`** access; LM **`chat`** calls still overlap. Unexpected executor failures emit **`workflow.failed`** on the Build SSE channel instead of silently ending the **`text/event-stream`** response.

- **Simple LLM + Gmail** — When **`user_prompt`** is a **string** slot wired from a curated Gmail message dict, the text sent to the model is a **compact JSON** of headers + **`body_text`** (or **`snippet`** if no body), omitting **`labelIds`** and other noisy fields; slimmed strings also **strip invisible/format Unicode** (e.g. U+034F, ZWSP, bidi overrides, category **`Cf`**) from those fields. Full message dicts are unchanged on **`output.data`** for downstream steps. See [docs/WORKFLOW_SKILLS.md](docs/WORKFLOW_SKILLS.md) and [`gmail_llm_prompt.py`](backend/app/domain/workflow_executor/gmail_llm_prompt.py).

### Backend / LM Studio

- **Authentication + load coordination** — Workflow runs send **`Authorization: Bearer`** using **`User.api_keys['lmstudio_api_key']`** (preferred) or **`LMSTUDIO_API_KEY`** env. **`GET /api/v1/models/`** (shared picker list) uses **`LMSTUDIO_API_KEY`** only (see **API / LM Studio** above). **`LMSTUDIO_BASE_URL`** remains server-only. Before chat, the provider may call native **`GET /api/v1/models`** / **`POST /api/v1/models/load`** (per-model lock) so parallel steps do not all fail while a model loads; transient chat errors **429** / **502** / **503** retry within **`LMSTUDIO_CHAT_RETRY_BUDGET_SECONDS`**. My Settings no longer exposes a per-user LM Studio base URL; **`lmstudio_base_url`** is removed from the **`api_keys`** allow-list. See [docs/OPERATIONS.md](docs/OPERATIONS.md), [backend/README.md](backend/README.md#environment-variables).

- **`PUT /auth/me` `api_keys` merge** — Masks secrets as **`[stored]`** on **`GET /me`**; saving settings without retyping a key no longer overwrites the real value with that literal (which caused **401** from LM Studio). **`[stored]`** in the merge is ignored. **Empty string** no longer overwrites an existing secret (omit keys you are not changing). Use **`null`** for a key to remove it. **`resolve_lmstudio_bearer`** ignores a decrypted value **`[stored]`** so **`LMSTUDIO_API_KEY`** env can still apply after a bad row. **My Settings → API Settings** uses **uncontrolled** password inputs read via **refs** on Save (no React `value` / hydration from **`[stored]`**), sends only non-empty key fields, skips the server **PUT** when nothing was typed (neutral message), and clears fields after a successful save.
- **`api_keys` decrypt** — If Fernet decryption fails (**`SECRET_KEY`** changed, corrupted DB row, or truncated paste), the entry is **omitted** (with a log warning) instead of passing the **`v1.`** ciphertext through as the secret, which LM Studio rejected with **401**. **`PUT /auth/me`** strips surrounding whitespace on incoming API key strings. **`resolve_lmstudio_bearer`** strips a leading Unicode BOM from pasted keys. Chat failures with LM Studio **401** raise a clearer **`ValueError`** message. See [backend/README.md](backend/README.md#lm-studio-401-unauthorized).

### Auth (breaking contract for old JWTs)

- **Access JWTs** must include the claim `typ: "access"`. **Refresh JWTs** must include a non-empty `jti` string.
- **After upgrading the API:** If `/me` or other authenticated routes return **401**, obtain a new session:
  - **Browser (HttpOnly cookies):** Sign in again, or use your normal session flow (e.g. refresh cookie + `POST /auth/refresh`); new tokens are issued with the correct claims.
  - **`Authorization: Bearer` clients:** Call login or refresh and **replace** the stored access token. The server cannot rewrite already-issued JWTs.
- There is **no server-side migration** for tokens minted before this rule; re-authentication is expected.

More context: [docs/OPERATIONS.md](docs/OPERATIONS.md) — *After a backend deploy — auth (JWT)*.
