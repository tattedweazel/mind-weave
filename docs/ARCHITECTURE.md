# Mind Weave — architecture and conventions

**Onboarding path:** Start with the root **[README.md](../README.md)** and **[DOMAIN_MODEL.md](DOMAIN_MODEL.md)** for staged orientation; use this document for engineering single sources of truth and implementation conventions.

If you need a **runtime system map** (browser, API, SSE, executor, persistence) with diagrams, read **[RUNTIME_ARCHITECTURE.md](RUNTIME_ARCHITECTURE.md)** first.

This document is the **single “one way” engineering guide** for layering, shared contracts, and cross-cutting patterns—**single sources of truth**, executor behavior, palette contracts, UI conventions, and contributor checklists—and is intentionally dense. Detailed how-tos stay in [backend/README.md](../backend/README.md) and [frontend/README.md](../frontend/README.md).

## Layers

| Layer | Backend | Frontend |
|--------|---------|----------|
| HTTP / UI | FastAPI routers under `app/api/v1/` | React components under `src/components/` |
| Domain | Services + Pydantic schemas under `app/domain/` | API clients under `src/api/` |
| Data | SQLModel tables under `app/persistence/` | TypeScript mirrors in `src/api/types.ts` |

**Companion / Workspace** — Interactive chat runtime with staged turns (interpret → route → **user-confirmed** capability execution → compose → deliver), persisted in dedicated tables (`companions`, `workspaces`, `workspace_sessions`, `workspace_turns`, `workspace_replays`, `companion_memory_entries`). Workflow capabilities use the same [`WorkflowExecutor`](../backend/app/domain/services/workflow_executor/__init__.py) as Build runs, with Start `input_overrides` derived from interpretation and a mandatory confirm step before any enabled workflow runs (see [WORKSPACE.md](WORKSPACE.md)). This is separate from one-shot **Workflow** execution from the editor and from **Sandbox** tick simulation.

Routers should stay thin: validate auth, call a service, map exceptions to HTTP. Business rules live in services.

## Single sources of truth

- **Workflow palette taxonomy and labels** — [`shared/workflow_graph_step_kinds.json`](../shared/workflow_graph_step_kinds.json) is the authoritative map of executable step kinds: each row carries **`palette_handle`** (persisted **`colors`** key), **`editor_label`**, **`kind`**, and discriminator fields aligned with persisted graphs. Pseudo-handles for editor-only and generic keys (**`annotation_note`**, **`annotation_region`**, **`any`**, **`workflow`**, family keys **`primitive`** / **`skill`** / **`utility`** / **`control`**, **`audio`**, **`start`** / **`stop`**, …) live in **`palette_extras`** in the same file. Backend parity tests enforce manifest ↔ [`DEFAULT_PALETTE_COLORS`](../backend/app/domain/palette_defaults.py) alignment.
- **Default workflow palette hex values** — [`backend/app/domain/palette_defaults.py`](../backend/app/domain/palette_defaults.py) owns **`DEFAULT_PALETTE_COLORS`** and built-in preset rows. **API palette responses** include derived **`entries`**, **`effective_colors`**, and **`warnings`** ([`workflow_palette_resolve.py`](../backend/app/domain/workflow_palette_resolve.py)): effective color for each handle is explicit override → same-palette family fallback → server default → **`any`**. The SPA reads **`effective_colors`** (or **`entries`**) from list/get/create/update payloads; [`paletteDefaults.ts`](../frontend/src/domain/paletteDefaults.ts) keeps **`resolveWorkflowPaletteColor`** and small emergency fallbacks only—full dual SSOT mirrors in TypeScript are **not** maintained.
- **Built-in workflow palettes** — `BUILTIN_WORKFLOW_PALETTES` (`BuiltinPalette`: `name`, `slug`, `colors`) in [`palette_defaults.py`](../backend/app/domain/palette_defaults.py). System rows (`user_id` NULL) have a unique **`slug`** (`default`, `slate`, …). [`PaletteService.initialize_builtin_palettes()`](../backend/app/domain/services/palette_service.py) matches by `slug` (or legacy `name`), **inserts** missing rows, and **overwrites** `name` / `colors` from code on each run so shipped presets stay aligned with **`DEFAULT_PALETTE_COLORS`** keys. **`POST /api/v1/palettes/`** and **`PUT …/{id}`** validate colors and keys (unknown keys **`422`**). **`POST /api/v1/palettes/validate`** returns the same **`entries`** / **`warnings`** shape **without persisting** (used for JSON import preview). **`GET /api/v1/palettes/resolve`** (optional **`workflow_id`**) returns the **effective** editor palette with server precedence: **`workflow.palette_id`** (when visible) → **`User.settings.preferred_editor_palette_id`** → built-in **default**. There is **no** separate **`GET …/active`** “stored active row” route. **`GET /api/v1/palettes/by-slug/{slug}`** returns a built-in by slug. The SPA calls **`/resolve`** for canvas colors and keeps [`resolveFallbackWorkflowPalette`](../frontend/src/domain/paletteDefaults.ts) only as an offline / error fallback; when **`workflow.palette_id`** is set locally, a palette from the list still wins for immediate unsaved UI.
- **OpenAPI-derived palette types** — Run `npm run codegen:palette-types` from **`frontend/`** (writes [`frontend/openapi.palette.json`](../frontend/openapi.palette.json) and [`frontend/src/generated/palette-types.ts`](../frontend/src/generated/palette-types.ts)). **`npm run verify:palette-types`** regenerates and fails on git drift; run it locally (or in any automation you add later) before merging palette/API changes. [`frontend/src/api/types.ts`](../frontend/src/api/types.ts) **`Palette`** shape should stay aligned with the generated **`components`** schemas.
- **Built-in system theme palettes** — `BUILTIN_SYSTEM_PALETTES` in [`backend/app/domain/system_palette_defaults.py`](../backend/app/domain/system_palette_defaults.py) (same **names/slugs** as workflow presets; each row has `colors: { light, dark }` maps of semantic UI tokens). Table `system_palettes` (`SystemPalette` in [`tables.py`](../backend/app/persistence/tables.py): `user_id` null + unique `slug` for built-ins). [`SystemPaletteService.initialize_builtin_system_palettes()`](../backend/app/domain/services/system_palette_service.py) syncs like workflow palettes. REST: `GET/POST /api/v1/system-palettes/`, `GET /api/v1/system-palettes/by-slug/{slug}`, `GET/PUT/DELETE /api/v1/system-palettes/{id}` (mutations user-owned only). **User settings:** `system_palette_id` (UUID string or null) is allow-listed in [`auth.py`](../backend/app/api/v1/auth.py); [`ThemeContext`](../frontend/src/contexts/ThemeContext.tsx) merges **defaults → preset → `system_colors`** per mode. SPA: [`systemPaletteImportExport.ts`](../frontend/src/domain/systemPaletteImportExport.ts), list ordering [`systemPaletteDisplay.ts`](../frontend/src/domain/systemPaletteDisplay.ts).
- **Workflow editor panel widths** — Optional browser persistence (per workflow id, `localStorage`, capped + LRU) is gated by **`User.settings.workflow_editor_remember_panel_widths`** (boolean; allow-listed in [`auth.py`](../backend/app/api/v1/auth.py); default **on** when the key is unset). Layout clamp helpers live in [`frontend/src/components/workflow-editor/workflowEditorPanelLayout.ts`](../frontend/src/components/workflow-editor/workflowEditorPanelLayout.ts); persistence in [`workflowEditorPanelWidthsStorage.ts`](../frontend/src/components/workflow-editor/workflowEditorPanelWidthsStorage.ts). On **viewports below Tailwind `lg`** ([`useCompactViewport`](../frontend/src/hooks/useCompactViewport.ts)), the palette and Explorer are **slide-over overlays** so the canvas uses the full main width; at `lg` and above, the editor keeps resizable side columns and `clampPanelWidths`. **Immersive fullscreen** (toolbar on the Workflows view, state in [`App.tsx`](../frontend/src/App.tsx)) hides the global nav and header and **forces the same overlay panel behavior** at any viewport width via `workflowEditorOverlayPanels`. **Sandbox** ([`SandboxView.tsx`](../frontend/src/components/SandboxView.tsx)) uses the same overlay split. **Favorite colors:** **`User.settings.sandbox_favorite_colors`** (list of up to 16 `#RRGGBB` strings; allow-listed in [`auth.py`](../backend/app/api/v1/auth.py); edited under **My Settings → View Settings → Favorite colors**) supplies swatches for color pickers (e.g. Sandbox region placement).
- **SPA shell URL (refresh-safe)** — The authenticated shell in [`App.tsx`](../frontend/src/App.tsx) mirrors the visible **Home / Workspace / Workflows / Sandbox** area in the browser path: `/` (default landing: Workspace when `VITE_WORKSPACE_ENABLED` is not `false`, else Home), `/workspace`, `/workflows`, `/workflows/{definition_uuid}`, `/sandbox` (when `VITE_SANDBOX_ENABLED` is not `false`). Sidebar navigation uses **`history.pushState`**; switching which workflow is open uses **`replaceState`** so **Back** moves between top-level areas only, not per-workflow. Helpers: [`frontend/src/appUrlState.ts`](../frontend/src/appUrlState.ts). Production static hosting must serve `index.html` for client paths (e.g. `try_files $uri $uri/ /index.html` in [docs/examples/nginx/mind-weave.conf.example](examples/nginx/mind-weave.conf.example)).
- **Workflow projects (folders)** — Table `workflow_projects` ([`tables.py`](../backend/app/persistence/tables.py)): single-level folders per user; **`name_lower`** is unique per user (`Shared` is reserved and seeded server-side). Each folder has **`sandbox_enabled`** (boolean, default **false**): when **true**, workflows in that project appear in Sandbox creature-brain and region-trigger pickers; **Shared** is always eligible regardless of the stored flag (PATCH ignores `sandbox_enabled` on Shared). `workflow_definitions.project_id` nullable FK; list and create flows ensure a **Shared** row per user via [`WorkflowProjectService.ensure_shared_project()`](../backend/app/domain/services/workflow_project_service.py). **`PUT /api/v1/workflow-definitions/{id}`** with a **`project_id`** that does not exist or is not owned by the user is **coerced** to that user’s **Shared** folder in [`WorkflowDefinitionService.update_workflow()`](../backend/app/domain/services/workflow_definition_service.py) (avoids “Invalid project” when the row is orphaned or after ownership claim). API: `GET/POST /api/v1/workflow-projects/`, `PATCH/DELETE /api/v1/workflow-projects/{id}` (**Shared** cannot be deleted; non-empty delete returns **409** unless **`delete_workflows=true`**, which cascade-deletes all definitions in the folder). Workflow definitions expose **`created_at`** / **`updated_at`** (UTC) on `GET`; list order is **`updated_at` DESC**, then id. SPA: [`WorkflowEditor.tsx`](../frontend/src/components/workflow-editor/WorkflowEditor.tsx) loads **workflow-definitions** before **workflow-projects** so folder counts stay consistent; project list → drill-in for import, new workflow, **delete project** (inline confirm; non-empty warns before cascade), **Enable in Sandbox** checkbox per project row (Shared checked and disabled), segmented sort, filter, and move; [`filterNamesByPrefix`](../frontend/src/components/workflow-editor/workflowListFilter.ts) matches palette step filters. Sandbox filters pickers client-side via [`workflowProjectMembership.ts`](../frontend/src/domain/workflowProjectMembership.ts) (picker-only; existing creatures keep running if a project is later disabled).
- **Board projects (folders)** — Table `board_projects` ([`tables.py`](../backend/app/persistence/tables.py)): single-level folders per user for **`sandbox_boards`** (independent from workflow projects; same **Shared** seed/backfill pattern). `sandbox_boards.project_id` nullable FK; [`BoardProjectService.ensure_shared_project()`](../backend/app/domain/services/board_project_service.py) on list/create. API: `GET/POST /api/v1/board-projects/`, `PATCH/DELETE /api/v1/board-projects/{id}` (**Shared** cannot be deleted; non-empty delete returns **409** unless **`delete_boards=true`**, which cascade-deletes boards in the folder). Board CRUD accepts optional **`project_id`** on create/update; **`POST …/sessions/{id}/save-board`** accepts **`project_id`** for **save_as_new**. System boards keep **`project_id = null`** and stay pinned outside project drill-in. SPA: [`SandboxView.tsx`](../frontend/src/components/SandboxView.tsx) — system boards at top, project list → drill-in (sort, filter, move, delete project, delete board per row + toolbar trash); helpers in [`boardProjectMembership.ts`](../frontend/src/domain/boardProjectMembership.ts). **`DELETE /api/v1/sandbox/boards/{id}`** existed before the UI; delete is now wired in the SPA.
- **Primitive text normalization (workflow editor)** — [`frontend/src/domain/normalizeText.ts`](../frontend/src/domain/normalizeText.ts): **`normalizeText(raw, kind)`** dispatches to **`normalizeTextAsList`** / **`normalizeTextAsDictionary`** (v1). Shared helpers **`stripCommonJsonWrappers`**, **`extractBalancedJsonSlice`**. **`NormalizationTiming`** and **`normalizationTimingForKind`** document when normalization runs: list/dictionary use **`explicit`** (user clicks **Normalize JSON**); future kinds (e.g. int) may use **`on_input`**. Invalid JSON inside strings (e.g. bad escapes) is not auto-repaired.

Details: [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md#markdown-preview).
- **Copy to clipboard + confirmation toast** — [`frontend/src/systemClipboard.ts`](../frontend/src/systemClipboard.ts) is the only production callsite for **`navigator.clipboard.writeText`**. UI code uses **`useCopyWithFeedback`** from [`ClipboardFeedbackContext`](../frontend/src/contexts/ClipboardFeedbackContext.tsx) (provider in [`main.tsx`](../frontend/src/main.tsx)) so every Copy action gets the same transient **Copied to clipboard** / **Could not copy** feedback; see [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md).
- **LLM workflow export JSON Schema (reference)** — [`shared/mind_weave_workflow_export_llm_response.schema.json`](../shared/mind_weave_workflow_export_llm_response.schema.json) is a **copy-paste** JSON Schema for **Structure** resources used with **Simple LLM Call** when you want structured output that matches the full **`mind_weave_workflow_export`** envelope (non-empty `edges`, **`nodes`** must **contain** both Start and Stop, Start/Stop `data` via `if`/`then` on `kind`). It is not loaded automatically by the server; hosts paste it into the Structure editor. See [WORKFLOW_EXPORT_FROM_PROMPT.md](../WORKFLOW_EXPORT_FROM_PROMPT.md) and [WORKFLOW_TOOL_INVENTORY.md](../WORKFLOW_TOOL_INVENTORY.md). Tests: [`backend/tests/test_mind_weave_workflow_export_llm_schema.py`](../backend/tests/test_mind_weave_workflow_export_llm_schema.py).
- **Workflow graph node discriminators (canvas import)** — Step types are identified by **`primitive_type`**, **`utility_type`**, **`control_type`**, **`skill_type`**, and (for editor-only annotations) **`annotation_type`** on **each node object** (siblings of **`kind`**), not nested under **`data`**. [`graphConverters.ts`](../frontend/src/components/workflow-editor/graphConverters.ts) **`hoistStepDiscriminatorsFromData`** lifts common LLM mistakes before mapping to React Flow; nodes that still cannot be mapped render as **`invalidStep`** (amber), not as **Stop**.
- **Domain Pydantic models** — [`backend/app/domain/schemas/`](../backend/app/domain/schemas/) package; use `from app.domain.schemas import ...` (stable public imports via `schemas/__init__.py`; avoids naming the package `types`, which shadows stdlib and breaks mypy).
- **Textual noise reduction** — [`backend/app/core/text_noise.py`](../backend/app/core/text_noise.py) is the single source of truth for cleaning HTML-derived bodies (Gmail today; reusable for any future integration whose extracts are noisy). **`NoiseFilterConfig`** is a frozen dataclass exposing every knob: line-ending normalization (`\r\n` / lone `\r` → `\n`), HTML-entity unescape, invisible / bidi character strip, `<style>` / `<script>` drop, repeated-separator collapse, tracking query-param strip from URLs (conservative allow-list of `utm_*`, `mc_cid`, `mc_eid`, `fbclid`, `gclid`, `_hsenc`, `_hsmi`, `ref`, `aff`, `cid`, `eid`, `mkt_tok`, etc.), long-URL shortening with `long_url_threshold`, orphan `[link]` placeholder-line drop, optional quoted-reply / marketing-footer stripping, whitespace collapse, and a final `max_chars` cap. Three presets ship from this module: **`DEFAULT_NOISE_FILTER`** (generic), **`EMAIL_BODY_NOISE_FILTER`** (used by Gmail body extraction in [`workflow_executor/diagnostics.py`](../backend/app/domain/workflow_executor/diagnostics.py) and by the LLM-prompt slimmer in [`gmail_llm_prompt.py`](../backend/app/domain/workflow_executor/gmail_llm_prompt.py); enables `strip_marketing_footers`), and **`EMAIL_HEADER_NOISE_FILTER`** (lighter touch for short fields like `subject` / `snippet` / `from` / `to` / `date` — invisible-char + entity cleanup + whitespace collapse only, no truncation, no URL changes, no footer stripping). Tune behaviour by editing a preset (or passing a per-call `NoiseFilterConfig`); never re-implement the same regexes elsewhere. Tests live in [`backend/tests/test_text_noise.py`](../backend/tests/test_text_noise.py).
- **Workflow executor Session concurrency** — Persisted Build runs enqueue with `POST …/workflow-definitions/{id}/runs` and execute on a background task with one SQLAlchemy `Session` tied to [`execute_workflow_run_job`](../backend/app/domain/workflow_run_runner.py). SQLAlchemy sessions are **not** safe for concurrent ORM access from overlapping `asyncio` tasks. `WorkflowExecutor` serializes DB access with `_async_session_lock` wherever parallel waves touch the session; **Simple LLM Call** loads `User`, **`session.refresh`es** the row when commits mutate run rows, decrypts **`api_keys`**, and resolves the LM Studio Bearer **inside** that lock; **`httpx`** chat runs **outside** the lock so LM Studio calls can overlap. Live progress streams on **`GET /api/v1/workflow-runs/{run_id}/events`** ([`workflow_run_events.py`](../backend/app/api/v1/workflow_run_events.py)); that route snapshots the DB from worker threads so sync ORM work does not stall the single event loop while background nodes run. **`GET /api/v1/models/`** (Persona/workspace model pickers) uses **`LMSTUDIO_API_KEY`** only—**not** per-user **`api_keys`**—so every user sees the same LM Studio catalog for the configured host. When adding new nodes that read the DB from parallel waves, keep ORM work under the same lock pattern; see [`executor.py`](../backend/app/domain/workflow_executor/executor.py).
- **Workflow execution** — Implementation in [`backend/app/domain/workflow_executor/`](../backend/app/domain/workflow_executor/); [`backend/app/domain/services/workflow_executor.py`](../backend/app/domain/services/workflow_executor.py) re-exports `WorkflowExecutor` for existing import paths. **LM Studio** — Host is **`LMSTUDIO_BASE_URL`** only; **`User.api_keys['lmstudio_api_key']`** (decrypted) or **`LMSTUDIO_API_KEY`** env supplies **`Authorization: Bearer`** for OpenAI-compat chat and native load/list ([`lmstudio_http.py`](../backend/app/providers/lmstudio_http.py), [`lmstudio.py`](../backend/app/providers/lmstudio.py)). **Parallel wave cap** — `User.settings.max_concurrent_lm_studio_calls` (integer **1–32**, default **3**; allow-listed in [`auth.py`](../backend/app/api/v1/auth.py); resolved in [`user_settings.py`](../backend/app/domain/user_settings.py)) limits how many **ready** nodes run in each `asyncio.gather` wave on the main schedule and inside **for-loop** body schedules. With **For Loop** **`parallel_iterations`** or **`iteration_mode` `parallel` / `batched`**, the same value also limits how many iterations (or batches) are **started at once**. Users tune it in **My Settings → System Settings**. **`WORKFLOW_MAX_CONCURRENT_NODES`**, **`WORKFLOW_MAX_CONCURRENT_LLM_CALLS`**, **`WORKFLOW_MAX_CONCURRENT_BROWSER_TASKS`**, **`WORKFLOW_MAX_CONCURRENT_EXTERNAL_SKILL_TASKS`**, and **`WORKFLOW_MAX_CONCURRENT_TTS_TASKS`** ([`config.py`](../backend/app/core/config.py)) add **`asyncio.Semaphore`** layers around each node via **`_node_execution_scope`** ([`executor.py`](../backend/app/domain/workflow_executor/executor.py)) with per-kind routing from [`workflow_node_extra_concurrency_bucket()`](../backend/app/domain/workflow_executor/concurrency.py): every execution holds a global node slot plus at most one of LLM / browser / **tts** / external buckets for node kinds that need it. **`_wave_cap_for_run`** still caps each wave using **`min`** of the effective LM cap (server env **`min`** user setting) and **`WORKFLOW_MAX_CONCURRENT_NODES`**. Tests that mock the LLM should patch `app.domain.workflow_executor.executor.LMStudioProvider` (the module where the provider is bound). **Execution limits** — Optional **`User.settings.workflow_execution_limits_prefs`** (sparse object; **`PUT /auth/me`**; same fields as **`graph.execution_limits`**) merges **between** deployment defaults and graph/run overlays; optional saved **`graph.execution_limits`** plus optional **`WorkflowRunRequest.execution_limits`** on **`POST …/run`** and **`POST …/runs`** sit **above** prefs on that stack (last wins per field): **run → graph → prefs → defaults**. Resolution and ceiling checks live in [`execution_limits.py`](../backend/app/domain/execution_limits.py) with knobs in [`config.py`](../backend/app/core/config.py) (`WORKFLOW_EXECUTION_DEFAULT_*` / `WORKFLOW_EXECUTION_CEILING_*`, plus **`WORKFLOW_MAX_LOOP_BATCH_SIZE_CEILING`** for batched loops). Users may set prefs in **My Settings → System Settings**. **`GET /api/v1/workflow-execution-limits/`** returns **defaults**, **ceilings**, and **`max_loop_batch_size`** for editor validation. Enqueued runs persist the resolved caps on **`WorkflowRun.execution_limits_effective`**. Optional **`WorkflowRunRequest.acknowledge_preflight_warnings`** opts into runs that matched advisory preflight estimates (see [`execution_preflight.py`](../backend/app/domain/execution_preflight.py), invoked from [`workflow_definitions.py`](../backend/app/api/v1/workflow_definitions.py)). The executor enforces **workflow TTL** (`asyncio.wait_for`), a **global step budget** aligned with streamed **`node.completed`/`node.failed`**, **max list iterations vs resolved `max_loop_iterations`** before a For Loop runs, and **nested workflow depth** vs **`max_nested_depth`**. **`Try / Catch`** (`control_type: try_catch`) — Regions and overlap rules are validated in [`graph.py`](../backend/app/domain/workflow_executor/graph.py); **`_run_try_catch_node`** ([`executor_resolver_mixin.py`](../backend/app/domain/workflow_executor/executor_resolver_mixin.py)) runs an inner topo-style scheduler for **`try`** and optional **`catch`**. Outputs include **`output`** / **`envelope`** dictionary payloads (`ok`, `value` or structured `error`); failed steps inside **`try`** that are routed to **`catch`** record **`handled_by_try_catch`** in **`details`** and (for streamed runs) SSE **`handled_by_try_catch`**. Global **DAG cycle detection** ignores edges whose only role is wiring a **`value`** input on a **`TryCatchControlNode`** (producer → TC **`value`**), since that closes an intentional feedback edge. **For Loop** — Beyond legacy **`parallel_iterations`**, **`data.iteration_mode`** may be **`sequential`**, **`parallel`**, or **`batched`** (`batch_size` clamped); optional **`continue_on_error`**, **`max_iterations`**, and a **`summary`** handle exposing an aggregated **`dictionary`** for runs that populate it (**`inputs.py`** + [`aux_outputs.py`](../backend/app/domain/workflow_executor/aux_outputs.py)). **Output overrides** — `POST .../run` and Build enqueue `POST .../runs` accept optional **`output_overrides`** (`node_id` → JSON) validated by [`workflow_output_overrides.py`](../backend/app/domain/workflow_output_overrides.py); matching nodes skip execution and receive the typed output; **`details.forced_output`** is set on the result. Overrides are rejected for nodes inside **for-loop bodies** (v1). If a paired **For Loop End** is overridden, the loop body does not run. Nested **Workflow** runs receive a filtered override map for the child graph only. **Conditional branching** — Nodes that emit [`ConditionalNodeOutput`](../backend/app/domain/workflow_executor/executor.py) with a `branch` of `"true"` or `"false"` (e.g. **Basic Conditional**, **Is/Gt/Lt/…**, **Between**) must be included wherever the run loop advances only successors on the active handle; [`graph.py`](../backend/app/domain/workflow_executor/graph.py) `_build_in_degree_and_adjacency` uses the same node set for merge-aware in-degrees. **And / Or / Xor** emit a **single boolean** output (not `ConditionalNodeOutput`); use **Basic Conditional** or comparison controls when you need **true/false** branch wires. **For loop bodies** — Before each iteration, the executor clears `outputs` for every node in the loop body, so a **List** primitive cannot accumulate across iterations. Use the **Add to List** utility (`add_to_list`) with required **list** and **value** inputs (any JSON-serializable item); inside a **For loop** body it keeps loop-scoped carry keyed by `(for_loop_id, node_id)` so each run appends to the real prior list. After the loop completes, the executor writes **final** `ListNodeOutput` for each **Add to List** in the body from that carry so downstream nodes can read stable list outputs. **For Loop End** (`control_type: for_loop_end`) is **not** part of the loop body: it runs on the **main** schedule after the paired **For Loop** node finishes. Set `data.for_loop_id` to the paired For Loop’s node id, connect **For Loop** `signal_out` → **For Loop End** `trigger`, and wire **named** export edges (`target_handle` = JSON key) from body nodes whose outputs should appear in the End node’s **dictionary** output. [`graph.py`](../backend/app/domain/workflow_executor/graph.py) excludes **For Loop End** from `for_loop_body_node_ids` so it is never run per iteration.
- **Text-to-Speech (local bridge)** — Workflow **Text-to-Speech** (`skill_type: text_to_speech`) calls a separate HTTP service in [`services/tts-bridge/`](../services/tts-bridge/) via [`tts_bridge.py`](../backend/app/providers/tts_bridge.py) (`httpx` only; no PyTorch in the main API). ## Async vs sync FastAPI endpoints

**Convention:** use ordinary `def` handlers for **CRUD-style routes** that only use a sync `Session` and domain services—this matches most routers under `app/api/v1/`.

Use **`async def` when the handler must `await`** async I/O. Example: [`models.py`](../backend/app/api/v1/models.py) `GET /models/` uses `httpx.AsyncClient` to call LM Studio, so it correctly stays async. Do not “downgrade” such routes to sync without switching to a synchronous HTTP client (and understanding thread-pool implications).

Document new endpoints consistently with siblings in the same router when behavior is similar.

## Dates and timestamps (UTC)

**Rule:** Any value that represents an **instant** (created/updated/expiry, token expiry, purge cutoffs, etc.) MUST be **UTC** and **timezone-aware**: a `datetime` with `tzinfo` set, normally `datetime.timezone.utc`.

**Why:** **Naive** datetimes (`datetime.utcnow()`, or `datetime.now()` without a zone) have no offset. Mixing naive and aware values — or relying on SQLite’s storage of instants — makes comparisons, serialization, and “is this expired?” logic **ambiguous** and environment-dependent.

**Do this:**

- Use [`utc_now()`](../backend/app/persistence/tables.py) for SQLModel `Field(default_factory=...)` on table columns.
- Use `datetime.now(timezone.utc)` when assigning timestamps inside services (same instant semantics).
- Declare new SQLAlchemy columns as `DateTime(timezone=True)` in Alembic migrations when the column is a point in time.
- For **external APIs** (Google Calendar, etc.), pass **RFC 3339** strings with an explicit offset or `Z` for UTC; document the skill/API contract when a string is user-supplied rather than server-generated.

**Avoid:**

- `datetime.utcnow()` (naive, labeled “UTC” only by convention).
- `datetime.now()` without `timezone.utc` (local wall clock).

When reading rows that might have been written by older code paths, normalize before compare (see `app/core/oauth_state.py` `_as_utc`).

## Stored workflow graph (`WorkflowDefinition.graph`)

Persisted graphs are JSON objects shaped like `{ "nodes": [...], "edges": [...] }` with an optional **`schema_version`** (integer) and optional top-level **`execution_limits`** `{ workflow_ttl_seconds?, max_node_executions?, max_loop_iterations?, max_nested_depth? }` merged at run-time (**defaults → optional `User.settings.workflow_execution_limits_prefs` → graph → per-run overrides**) under server ceilings ([`execution_limits.py`](../backend/app/domain/execution_limits.py)). On **create** and **update**, [`WorkflowDefinitionService`](../backend/app/domain/services/workflow_definition_service.py) sets `schema_version` to **1** when it is missing or null so clients can rely on the field after save. Older rows without the key are treated as **implicit v1**; the executor still reads only `nodes` and `edges`, so unrecognized top-level keys are ignored unless explicitly handled (same pattern as optional **`sandbox_defaults`** `{ grid_width, grid_height }` for new sandbox sessions—see [SANDBOX.md](SANDBOX.md)). The **built-in starter sandbox** workflow (`builtin_slug` **`starter_sandbox_behavior`**) is stored in the same **export-shaped** form—**`nodes` + `edges` only** (implicit v1)—matching editor exports; app startup [`ensure_starter_sandbox_workflow`](../backend/app/domain/sandbox/starter_workflow_seed.py) and Alembic revision **`e1f2a3b4c5d6`** keep that row aligned with the canonical graph in code. Regression tests also compare that graph to repo-root **`sandbox-behavior-imported.json`**; when you change the seed, regenerate that file (see **Starter graph export fixture** in [SANDBOX.md](SANDBOX.md) and the docstring in [`starter_workflow_seed.py`](../backend/app/domain/sandbox/starter_workflow_seed.py)).

**Google workflow OAuth** — Skill nodes **`gmail_list_messages`**, **`calendar_list_events`**, and **`google_docs_get_document`** resolve the user’s single workflow Google connection at run time via [`get_user_workflow_google_connection`](../backend/app/integrations/google_workflow_connection.py) (My Settings → Google for workflows). Legacy **`data.google_connection_id`** on stored graphs is ignored. See **`test_google_workflow_connection.py`** and **`test_workflow_executor_nested_google.py`**.

**Editor-only annotations** — The Workflow Editor may persist **`kind: "annotation"`** nodes with **`annotation_type`** **`note`** or **`region`** (sticky notes and resizable layout frames). On the canvas, a **note** shows its persisted **`label`** (Explorer **General → Label**) in the header chrome (**`data.label_font_size_px`** vs **`data.content_font_size_px`** for the body); the note body is **`data.text`**, and **`data.width` / `data.height`** (with React Flow **`style`**) size the card like **regions**. **Note** canvas alignment is controlled independently by **`data.label_align`** and **`data.content_align`** (each **`left`**, **`center`**, or **`right`**; default **`left`** when omitted)—these affect only the **canvas** note; the Explorer **Note appearance → Content** textarea stays left-aligned for editing. **Regions** use **`data.label_align`** the same way for the floating label chip. **Stacking:** Both **notes** and **regions** persist **`data.z_index`**, mapped to React Flow **`zIndex`** and adjusted via Explorer **Stack order** (**Move back** / **Move forward**) under **Note appearance** and **Region appearance** ([`AnnotationStackOrderControls.tsx`](../frontend/src/components/workflow-editor/AnnotationStackOrderControls.tsx); clamps in [`graphConverters.ts`](../frontend/src/components/workflow-editor/graphConverters.ts)). **Regions** use the band **`−1000`…`−1`** (default **`−10`**); **notes** use **`0`…`999`** (default **`0`**) so regions stay behind notes; workflow **edges** use **`zIndex: 1000`** on the canvas so connections draw above annotations. They are **not** executable: [`_parse_node`](../backend/app/domain/workflow_executor/parsing.py) returns **`None`** for `kind: "annotation"` (no warning), so they never enter the executor’s `nodes_by_id`. They are **not** listed in [`shared/workflow_graph_step_kinds.json`](../shared/workflow_graph_step_kinds.json); the SPA registers their React Flow types in [`stepKindRegistry.ts`](../frontend/src/components/workflow-editor/stepKindRegistry.ts) beside the manifest map.

## Resource-backed primitives (Documents; future Personas)

**Documents** are first-class resources (like **Personas** and **Structures**): SQLModel table with globally unique **`name`**, thin FastAPI router, domain service with the same visibility rules (read user-owned + system rows; create/update/delete only user-owned), and a **Configure** modal in the SPA. The body editor exposes three tabs — **Raw** shows the exact stored **`body`** text, **Preview** runs the Markdown pipeline when the content is authored as Markdown (JSON or other text still appears sensibly in **Raw**), and **Metadata** shows derived size statistics (token / character / word / line counts) plus the document id and timestamps. The **`body`** column is **general-purpose text**: Markdown, JSON, serialized workflow fragments, config, or hybrid content. The row does **not** enforce a schema—**Structures** remain optional contracts; workflows interpret content.

**Metadata endpoint and tokenizer:** **`GET /api/v1/documents/{id}/metadata`** returns a separate **`DocumentMetadata`** payload computed by [`document_metadata_service.compute_document_metadata`](../backend/app/domain/services/document_metadata_service.py) using `tiktoken` with the **`o200k_base`** encoding (GPT-4o family). The number is an **estimate** — local LM Studio models may use a different tokenizer — and the SPA labels it as such. The slim list and full-get document shapes are unchanged; the SPA fetches metadata lazily the first time a focused document's **Metadata** tab is opened, caches it per-id, and invalidates on save. Unsaved/new documents show a "Save the document to see token count" hint instead of issuing a request.

Workflows can reference a saved document with a **Document** primitive (`primitive_type: "document"`), which loads the row by id and emits **`DocumentNodeOutput`** (`kind: "document"`). The complementary **persist** path is **`upsert_document`**: supply **`name`** and string **`content`** (e.g. a formatted transcript) to create or update a user-owned row and emit the same document shape—default **`replace`** overwrites **`body`**. Utilities **`load_document`** (by id or name) and **`upsert_document`** (replace, append, or strict **`merge_json`** on JSON objects) also read and write via **`DocumentService`**.

**Upsert wires:** **`_resolve_inputs_by_target_handle`** maps edges whose **`target_handle`** is missing or null onto still-empty **`name`** / **`content`** string ports in deterministic order (**`implicit_null_target_wire_string_keys`** is passed only by this resolver). Before that, **`_normalize_edges_for_upsert_document`** rewrites mistaken body handles **`output`**, **`text`**, **`body`**, and **`markdown`** to **`content`**. Persisted graphs that store **`target_handle: "name"`** for a body wire while Explorer holds the title are **recovered** by **`_recover_upsert_miswired_body_into_content`** when **`content`** is still empty and there is no explicit **`content`** edge.

The SPA maps null **`target_handle`** on **`upsertDocument`** to **`content`** when Explorer **`name`** is set and **`content`** inline is blank, and maps the same alias handles to **`content`** on load so the next **Save** persists **`target_handle: "content"`**.

Additional utilities parse JSON from a document-shaped input (**`parse_document_body`**), serialize dict/list to deterministic JSON text (**`write_object_to_document_body`**), append serialized values to body text without persisting (**`append_value_to_document`**), and validate a value against a **Structure**’s JSON Schema (**`validate_against_structure`**).

Persisted node output still uses the wire field **`markdown`** for the document body text (historical name; semantically **stored text**), not a top-level **`body`** key, so run-log redaction does not treat it like a prompt field; **`workflow_executor/inputs.py`** maps **`DocumentNodeOutput`** to a plain dict for utilities and includes a **`body`** key aliasing that text so **Read Document Property** can use **`target_property: "body"`** like other named fields. When the target **`required_inputs`** slot is typed **`string`**, resolution passes **only** that body text (not the dict). The **Build** canvas allows wires from **Document** / **Load Document** / **Upsert Document** outputs into **`string`** and **`any`** handles via [`workflowConnectionRules.ts`](../frontend/src/components/workflow-editor/workflowConnectionRules.ts); other types (e.g. **`dictionary`**) stay blocked unless the node already has a dedicated **`document`** port.

**Workflow bundle export/import (editor):** **Export** / **Copy** on the Build toolbar produce **`mind_weave_workflow_bundle_export`** JSON (nested workflows, personas, structures, documents, palettes; see [OPERATIONS.md](OPERATIONS.md)). **Import** recreates rows under the importer’s user and remaps graph ids. LLM-authored exports remain single-workflow **`mind_weave_workflow_export`** v1 ([WORKFLOW_EXPORT_FROM_PROMPT.md](WORKFLOW_EXPORT_FROM_PROMPT.md)).

**Custom Skills (workflows as reusable steps):** A workflow definition may set **`expose_as_custom_skill`** so the editor’s **Custom Skills** palette lists it (same **`kind: "workflow"`** node and executor path as dragging a workflow from the project list; **`workflow_id`** is preset on drop). On the canvas, the **top** line of the nested step is **Custom Skill** when the referenced definition is exposed, and **Workflow** otherwise. The read-only **Node** field in the Explorer is the **referenced definition’s name**; the **Label** field edits **`data.label`**, which is the **second line** on the node and the value persisted in the graph (it is not replaced by the live referenced workflow name). Exposed definitions are omitted from the per-project **Workflows** drill-in list (they are opened and moved between projects from **Custom Skills**); the active definition still appears in **Custom Skills** with drag disabled to prevent self-nesting. The workflow **list** API returns rows **without** **`graph`**; the SPA **GETs each referenced definition** (by **`workflow_id`** on the canvas) so nested-node **data handles** match the child **Start** / **Stop** contract—see [MIND_WEAVE_ONE_PAGE.md](MIND_WEAVE_ONE_PAGE.md) (Left column: Workflows).

Adding another resource-backed primitive later (e.g. **Persona** on the canvas) should follow the same checklist: **manifest** row in [`shared/workflow_graph_step_kinds.json`](../shared/workflow_graph_step_kinds.json) → Pydantic node model + output type + parsing + executor + **`inputs.py`** wiring → TypeScript types, palette keys, editor node + inspector + converters → backend/frontend parity tests and CRUD smoke.

## Sandbox (board-driven multi-creature simulation)

**Sandbox V2.4** is a **server-owned** tick engine with **board templates** (`sandbox_boards`), **document-backed** sessions, and **per-creature workflow brains**. Each tick runs every creature's workflow once and applies **one atomic navigation action** (`move_forward`, `turn_left`, `turn_right`, `idle`). Types: [`shared/sandbox_canonical.schema.json`](../shared/sandbox_canonical.schema.json) (`schema_version: 2.4.0`, `creatures[]` with `facing` and optional `color`; region underlays with `color` and **`label`**, exposed to brains via **Get nearby** and **Get position** `region_label`). Full API, utilities, and UI tabs: [SANDBOX.md](SANDBOX.md), [BOARDS.md](BOARDS.md). The SPA renders the board with Phaser as a **view-only camera viewport** (scroll-wheel and pinch zoom, +/−/fit controls, auto-fit on load/resize) in [`phaserSandboxAdapter.ts`](../frontend/src/sandbox/runtime/phaserSandboxAdapter.ts).

## Database configuration (SQLite)

[`db.py`](../backend/app/persistence/db.py) creates the SQLAlchemy engine and registers a `connect` event listener that sets **`PRAGMA journal_mode=WAL`** on every new connection (SQLite only). WAL mode allows concurrent readers and writers, which prevents startup seed writes from blocking the frontend's first API requests.

## Backend startup optimizations

The FastAPI [`lifespan`](../backend/app/main.py) function runs Alembic migrations, seeds default data, and purges old workflow runs on every startup. Each phase is timed via `mindweave.perf` logging (see **Request timing middleware** below).

- **Schema management** — Alembic `upgrade head` runs on startup; `create_db_and_tables()` is **not** called because migrations already bring the schema to head, avoiding a redundant metadata reflection scan on the database. After migrations, the root logger level is restored to INFO because Alembic's `fileConfig()` sets it to WARNING (see `alembic/env.py` — `disable_existing_loggers=False` is set so Alembic does not clobber uvicorn's or application loggers).
- **Palette / system palette seeding** — [`PaletteService.initialize_builtin_palettes()`](../backend/app/domain/services/palette_service.py) and [`SystemPaletteService.initialize_builtin_system_palettes()`](../backend/app/domain/services/system_palette_service.py) compare `name` and `colors` before writing. If the existing row already matches the SSOT, the UPDATE + commit is skipped entirely. This avoids ~14 unnecessary writes on every restart.
- **Workflow run purge** — `_purge_old_workflow_runs()` uses **bulk `DELETE`** statements (`DELETE FROM node_run_logs WHERE run_id IN (...)` then `DELETE FROM workflow_runs WHERE ...`) instead of per-row ORM deletes. The `ix_workflow_runs_created_at` index (added in migration `n2o3p4q5r6s7`) keeps the initial filter query efficient as the table grows.
- **Bootstrap endpoint** — [`POST /workspaces/bootstrap`](../backend/app/api/v1/workspaces_api.py) uses `LIMIT 1` queries (`get_or_create_default_workspace` and `get_latest_session`) instead of loading all workspaces and sessions, reducing per-request DB queries from ~6 to ~3.

## Request timing middleware

[`RequestTimingMiddleware`](../backend/app/main.py) logs every HTTP request's **method**, **path**, **status code**, and **wall-clock duration** (ms) to the `mindweave.perf` logger. Each response also includes a **`Server-Timing`** header (`total;dur=<ms>`) so browser DevTools and [`scripts/measure-api-timing.sh`](../backend/scripts/measure-api-timing.sh) can surface backend latency without parsing logs. Startup lifespan phases (migrations, seed + purge) are logged to the same logger with their own timing labels.

## Slim list schemas (API payload optimization)

List endpoints for heavy resources return lightweight schemas that **exclude** large fields not needed for list/sidebar views:

| Endpoint | Schema | Excluded field |
|----------|--------|----------------|
| `GET /workflow-definitions/` | `WorkflowDefinitionListItem` | `graph` |
| `GET /documents/` | `DocumentListItem` | `body` |
| `GET /personas/` | `PersonaListItem` | `system_prompt` |

Full objects (with all fields) are still returned by single-item `GET .../{ id }` endpoints. The frontend fetches the full object on demand (e.g. when opening a workflow in the editor, selecting one in Sandbox, or editing a persona in Persona Manager).

**Detail editors must call the single-row endpoint.** Casting a list row at runtime to its full schema returns `undefined` for excluded fields (the field is missing from the JSON, not just narrow-typed). Editors that surface a heavy field — e.g. **Manage Documents** **Body**, **Persona** **System prompt**, the full **WorkflowDefinition** **graph** — must call **`GET /<resource>/{id}`** when a row gains focus and hydrate the editor from that response, ignoring stale results when the user picks another row mid-flight (focus-token ref). Canonical example: [`DocumentManager.tsx`](../frontend/src/components/DocumentManager.tsx) (`hydrateFocusBody`); the same component also shows the lazy-load + per-id cache + save-invalidation pattern via `loadMetadata` for the **Metadata** tab against **`GET /documents/{id}/metadata`**.

`list_workflows` is a **pure read** — orphan-project assignment (assigning `project_id` to owned workflows missing one) runs in `claim_orphan_if_needed` during create/update/run, not on every list call.

## Frontend code splitting and bundle strategy

[`App.tsx`](../frontend/src/App.tsx) lazy-loads heavy view components via `React.lazy` + `Suspense`:

- **`WorkflowEditor`** — code-split chunk containing `@xyflow/react`, the canvas, inspector, palette, and all step-type UI. Loaded only when the user navigates to the **Workflows** tab.
- **`RunExploreModal`** (Replays) — code-split chunk loaded only when the Replays modal opens; shares the `@xyflow/react` vendor chunk with the editor.
- **`WorkspaceView`** — code-split chunk for the Companion chat runtime.
- **`SandboxView`** — code-split chunk containing Phaser.

**All modals** — PersonaManager, PaletteManager, StructureManager, DocumentManager, UserManagement, and MySettings — are **lazy-loaded** via `React.lazy` with `Suspense` and only mount when the user opens them. This keeps the markdown rendering pipeline (`react-markdown`, `rehype-katex`, `remark-gfm`, `remark-math`) and admin/settings code out of the initial bundle. **Eagerly loaded** (in the initial bundle): `Login`, nav shell, `UserAvatar`, and contexts (`AuthContext`, `ThemeContext`, `ClipboardFeedbackContext`).

[`vite.config.ts`](../frontend/vite.config.ts) uses a `build.rollupOptions.output.manualChunks` function to isolate `react`/`react-dom`, `@xyflow/react`, the markdown stack (`react-markdown`, `remark-gfm`, `remark-math`, `rehype-katex`), and `phaser` into separate cacheable vendor chunks. **Mermaid** is dynamically imported inside [`MermaidBlock.tsx`](../frontend/src/components/MermaidBlock.tsx) and loads only when a mermaid code block renders. **`optimizeDeps.include`** explicitly lists all known heavy dependencies (`react`, `react-dom`, `lucide-react`, `react-markdown`, `remark-gfm`, `remark-math`, `rehype-katex`, `@xyflow/react`, `phaser`, `mermaid`, `katex`) so the Vite dev server pre-bundles them on startup rather than discovering them mid-page-load (which would trigger a full-page reload and re-optimization).

**Data fetching in the Workflow Editor:** [`WorkflowEditor.tsx`](../frontend/src/components/workflow-editor/WorkflowEditor.tsx) shows a loading spinner via `isDataLoading` state while the initial `loadAll()` completes (7 API calls fired in a single `Promise.all`: workflows, projects, personas, palettes, structures, documents, and google-connections). After mutations (save, create, delete, move), only the affected resources are refetched via `refreshWorkflowLists()` (2 parallel calls) instead of the full `loadAll()`.
